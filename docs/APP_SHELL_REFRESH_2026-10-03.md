# 2026-10-03 应用外层设计整理

## 范围

本轮只整理应用界面与现有操作的呈现方式。简历输出模板、模板登记表、分页与 PDF 渲染、导出逻辑、数据结构以及扩展权限均不修改。我的简历入口的位置、名称与点击处理函数保持原样。

## 操作与视觉变化

- 编辑区与成品区分别标明“编辑内容”“成品预览”；编辑区仅显示当前编辑的模块，不增加指导长文
- 设置从长列表改为“导入与备份 / 编辑与导出 / 高级设置”三个目的明确的分类；切换分类不触发文件操作，已有设置值和功能保留
- 模板分类从容易被裁断的横向标签改为带名称的完整下拉框；当前模板有文字标记，收藏与对比不再依赖悬停才能发现
- 模板预览的缩放位于纸面附近；低频的密度、配色与头像底色集中于默认收起的“排版设置”，原控制值和处理逻辑保留
- 应用画布、弹窗、设置、表单和富文本工具统一为中性灰白底、单一强调色、轻边框和一致控件；去掉重复的外框和较重的选中阴影
- 设置与模板页面沿用同一品牌标识；关闭、主操作、选中状态和键盘焦点采用统一规则

## 我的简历入口调查

已沿源代码验证：原生 type=button 在简历库就绪后可用，点击只设置 libraryOpen，随后挂载 ResumeLibraryDialog 并调用原生 dialog.showModal。此入口没有外部请求、权限申请、下载或页面导航。

将导航测试里对 Modal 的整体模拟移除，改用真实 Modal 组件，仅替代 JSDOM 缺少的原生 top-layer API。测试贯通点击、showModal、列表内容、关闭、重复打开、Escape 和焦点返回，编辑器实例与未离开页面的输入保留。相关 27 项检查通过。它证明组件事件链能够工作，不等同于真实浏览器点击验收。

先前桌面动作的返回是“JavaScript execution did not receive approval”，未取得应用点击后的结果。已有用户手动打开记录以及上述组件证据均不足以证明应用本身有点击缺陷，也不能确定工具拒绝的底层原因。因此没有为此修改按钮、添加替代路由或声称样式修正解决了拒绝。
